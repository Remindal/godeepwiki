# DeepWiki(Go版) 企业级技术栈变更总纲 v2.0

> 本文件是三份设计文档（00 设计基线 / 01 API 正式版 / 02 脚手架指令）重写时的**唯一权威契约**。
> 所有子文档中涉及技术栈、基础设施、配置、错误码、包结构的内容，必须与本总纲逐字一致。

## 0. 变更总览（一句话版）

把单机轻量原型栈（SQLite + bleve + go-git + 进程内队列/限流/事件总线 + 自研迁移器 + 手写 net/http）
整体替换为企业级可水平扩展栈（PostgreSQL 16 + pgvector + OpenSearch + RabbitMQ + Redis 哨兵集群 + etcd + git CLI + 各厂商官方 SDK + golang-migrate），
**REST 契约、状态机、事件协议、限流规则数值全部冻结不变**。

## 1. 技术栈替换矩阵（权威）

## 2. 冻结项清单（v1→v2 一字不改，各文档必须原样保留）

1. **REST 契约**：全部端点路径/方法/请求字段/响应字段（ingest、repos CRUD、refresh、tasks 查询/取消、ask、ask/stream、wiki generate/get、config GET/PUT、events SSE、ws、health、metrics）。
2. **统一响应信封**：`{code,message,data,request_id}`；错误信封 `{code,message,request_id,details?}`；分页 `{items,total,page,page_size}`。
3. **状态机**：ingest `pending→cloning→parsing→chunking→embedding→persisting→completed`；refresh `pending→fetching→diffing→chunking→embedding→persisting→completed`；wiki `pending→outlining→generating→completed`；终态 `failed/cancelled`；全部合法 state 枚举不变。
4. **进度权重**：ingest 15/10/10/50/15；refresh 20/10/10/45/15；wiki 10/90。
5. **事件协议**：`task.state_changed` / `task.progress` / `wiki.page_generated` 等事件名与 payload 结构；SSE `Last-Event-ID` 回放语义；WS `seq` 单调递增 + `resume_from`。
6. **ID 规范**：`tsk_/repo_/chk_/req_/wk_ + ULID(26)`，正则 `^(tsk_|repo_|chk_|req_|wk_)?[0-9A-HJKMNP-TV-Z]{26}$`。
7. **时间规范**：UTC + RFC3339（`2026-07-05T08:30:00Z`）。
8. **限流规则与数值**：L1 per-IP（`per_ip.rps`/`per_ip.burst`，默认 rps=5 burst=20，作用于全部端点）；L2 per-API-key 配额（`ingest_per_hour=20`、`ask_per_minute=30`、`wiki_per_hour=10`，作用于昂贵端点）；响应头 `Retry-After` / `X-RateLimit-Limit` / `X-RateLimit-Remaining` / `X-RateLimit-Reset`；429 错误体不变。**仅替换存储实现（进程内桶 → Redis Lua 滑动窗口），语义与数值不动。**
9. **错误码体系**：v1 全部错误码保留（10000/40001/40101/40301/40401/40402/40901/42201/42901/42902/50001/50002/50003/50004/50201/50202/50301 等），v2 仅**新增** §6 所列 4 个基础设施错误码。
10. **鉴权头**：`X-API-Key`；admin key 用于 PUT /config；密钥脱敏规则（长度>8 → 前3+***+后4，否则 ******）。
11. **验收接口三件套**：`POST /api/v1/ingest`、`GET /api/v1/tasks/{id}`（对应题目 `GET /api/ingest/:id/status`，路径以 v1 契约为准并在文档中注明映射）、`POST /api/v1/ask`。

### 3.2 生产部署拓扑（文档必须画出）

```text

   Client ──LB──▶│ API 节点 × N  │（无状态：Gin + 限流中间件 + SSE/WS 推送）
                 └──┬───┬───┬───┘
                    │   │   │
   ┌────────────────┘   │   └──────────────────┐
   ▼                    ▼                      ▼
┌─────────┐      ┌────────────┐        ┌─────────────┐
│Postgres │      │  RabbitMQ   │        │ Redis 哨兵集群│
│+pgvector│      │  队列集群   │        │(1主2从3哨兵) │
└─────────┘      └─────┬──────┘        └─────────────┘
                       │ consume          ▲
                 ┌─────▼──────┐           │
                 │Worker 节点×M│───────────┘（分布式锁/限流/事件总线）
                 └─┬────────┬─┘
                   ▼        ▼
            ┌───────────┐ ┌──────────┐
            │ OpenSearch │ │  etcd    │   + 共享卷（仓库工作目录）
            │  3 节点    │ │  3 节点  │
```

- **API 节点无状态**：不持有任务执行、不持有本地索引；SSE/WS 连接的状态（订阅关系）仅内存，事件经 Redis Pub/Sub 扇入。
- **Worker 节点**：消费 RabbitMQ；仓库工作目录需共享卷（`./data/repos` 挂载 NFS/PVC），或单 worker 节点本地盘（课程/中小企业规模推荐后者，文档两种形态都写）。
- **配置**：yaml+env 只引导「基础设施坐标」（DSN、endpoints）；运行时业务配置全部在 etcd。

## 4. 各组件详细设计决策（三份文档共用，不得偏离）

### 4.1 PostgreSQL + pgvector（R1/R2/R4/R14/R15）

- **连接**：`pgxpool.New(ctx, dsn)`，`MaxConns=10, MinConns=2, MaxConnLifetime=1h, HealthCheckPeriod=30s`；DSN 仅由环境变量 `DEEPWIKI_POSTGRES_DSN` 注入。
- **迁移**：golang-migrate，`iofs` source 嵌入 `migrations/*.up.sql`（命名 `000001_init.up.sql` 起，**只有 .up 没有 .down**，只前进原则不变）；启动时 `migrate.Up()`，dirty 状态 panic 退出并提示 `migrate force`。
- **pgvector**：`CREATE EXTENSION IF NOT EXISTS vector;`；`chunks.embedding vector(1536)`（维度在 `embedding.dimensions` 配置项，默认 1536，建表即定型；改维度 = 新迁移 + 全量重建，文档写明流程）。
- **HNSW**：`CREATE INDEX idx_chunks_embedding_hnsw ON chunks USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 128);`；查询时 `SET LOCAL hnsw.ef_search = 64;`（配置项 `retriever.vector.ef_search`）。
- **向量检索 SQL（VectorRetriever 唯一实现）**：

```sql
SET LOCAL hnsw.ef_search = 64;
SELECT chunk_id, path, start_line, end_line, language, content,
       1 - (embedding <=> $2) AS score
FROM chunks
WHERE repo_id = $1
  AND ($3::text IS NULL OR path LIKE $3)   -- 按文件路径过滤（进阶要求）
ORDER BY embedding <=> $2
LIMIT $4;
```

- **表结构变更**：时间列全部 `timestamptz`；CHECK 约束不变；`config_overrides`/`config_audit` 两表**移除**（迁往 etcd）；`chunks.vector BLOB` 列**移除**（由 `embedding vector(1536)` 取代）；`schema_version` 表**移除**（golang-migrate 自建 `schema_migrations`）；**新增 `api_keys` 表**：

```sql
CREATE TABLE IF NOT EXISTS api_keys (
    key_id      TEXT PRIMARY KEY,                 -- key_ + ULID
    name        TEXT NOT NULL DEFAULT '',
    key_hash    TEXT NOT NULL UNIQUE,             -- SHA-256(salt ‖ key) 十六进制
    salt        TEXT NOT NULL,
    is_admin    BOOLEAN NOT NULL DEFAULT FALSE,
    revoked_at  TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

启动时把 `DEEPWIKI_API_KEYS` / `DEEPWIKI_ADMIN_KEY` 中的明文 key 哈希后 upsert（幂等：已存在同 hash 则跳过）。留空 = 开发模式（跳过鉴权并 WARN，语义不变）。

- **repos/tasks/chunks/wiki_pages** 四表字段与 v1 完全一致（仅 TEXT 时间列换 timestamptz、`stats_json/progress_json/error_json` 升级为 **JSONB**、索引保留）。
- **级联删除矩阵不变**：DB 事务内 CASCADE → 事务提交后删 OpenSearch 索引 + 本地目录（外部资源失败只 ERROR + 后台重试清理，不回滚 DB）。删除顺序中「bleve 索引」字样全部改为「OpenSearch 索引（`deepwiki-chunks-<repo_id 小写>`）」。
- **维度一致性双保险**：① 应用层探测（provider/model/base_url 变更且库中有 chunks → `Embed(["dimension probe"])` 比对，不一致拒 42201）；② DB 层 `vector(1536)` 类型直接拒绝维度不符写入。两条都写进文档。

### 4.2 OpenSearch（R3）

- **索引隔离**：每仓一索引 `deepwiki-chunks-<repo_id 全小写>`（OpenSearch 索引名必须小写；repo_id 含大写 ULID，统一 `strings.ToLower`）。
- **Mapping**：

```json
{
  "settings": { "number_of_shards": 1, "number_of_replicas": 0, "analysis": {
      "analyzer": { "code_analyzer": { "type": "pattern", "pattern": "[^\\p{L}\\p{N}_.]+", "lowercase": true } } },
    "index.similarity.default.type": "BM25" },
  "mappings": { "properties": {
    "chunk_id":   { "type": "keyword" },
    "repo_id":    { "type": "keyword" },
    "path":       { "type": "text", "analyzer": "code_analyzer", "fields": { "raw": { "type": "keyword" } } },
    "content":    { "type": "text", "analyzer": "code_analyzer" },
    "language":   { "type": "keyword" },
    "start_line": { "type": "integer" },
    "end_line":   { "type": "integer" } } }
}
```

- `_id = chunk_id`；Persist 阶段 Postgres 事务提交成功后再 bulk 写入 OpenSearch（顺序约定不变）。
- **启动一致性校验**：每仓 `count(index) == chunks 表行数`，不一致 → WARN 并后台重建该仓索引（原 bleve 校验逻辑平移）。
- KeywordRetriever 查询：`multi_match` 于 `content^2, path`，`filter: term repo_id`（索引内天然隔离可省略，保留 filter 防御），BM25 默认排序；支持 `path_filter`（term `path.raw` 前缀匹配用 `prefix` 查询）。
- 生产 3 节点时 `number_of_replicas: 1`，dev 单节点 0 副本（compose 参数化）。

### 4.3 RabbitMQ（R9）

- **拓扑**：direct exchange `deepwiki.tasks`；队列 `deepwiki.task.jobs`（`x-max-length = worker.queue_size`（默认 100）、`x-dead-letter-exchange = deepwiki.tasks.dlx`）；DLQ `deepwiki.task.dlq`；重试队列 `deepwiki.task.retry.{5s,30s,5m}`（TTL + DLX 回流主队列，最多 3 次）。
- **瘦消息协议**：body = `{"task_id":"tsk_...","type":"ingest|refresh|wiki"}`，**禁止把任务状态/进度塞进消息**（任务状态唯一来源 = Postgres `tasks` 表，原约束 #3 精神平移）。
- **投递路径**：API 节点在 Postgres 事务内插入 `tasks`（pending）→ 事务提交 → `Channel.Publish`（`mandatory=true` + publisher confirm）；confirm 失败 → 标记任务 failed（`50302 queue_unavailable`）并返回 503。投递前 `QueueDeclarePassive` 读 `Messages` 深度，≥ x-max-length → 42902 + Retry-After（原背压契约平移）。
- **消费路径**：每 worker 节点 `prefetch = worker.pool_size`（默认 2）；收到消息 → 读 Postgres 校验任务仍为 pending（CAS：`UPDATE tasks SET state='cloning' ... WHERE task_id=$1 AND state='pending'`，CAS 失败直接 ack 丢弃，防多节点重复执行）→ 执行 pipeline → 终态落库后 **ack**；panic/recover 或瞬时错误 → **nack requeue=false** 进 DLX 重试链；重试耗尽 → failed（50003）。
- **重启恢复（Reconciler）**：worker 启动时扫描 Postgres 中非终态任务：pending 且无消费者持有 → 重新投递；running 态且 `updated_at` 超 5 分钟无心跳 → 重置 pending 重投（幂等 CAS 保证安全）。
- **优雅退出**：SIGTERM → readiness fail → `Channel.Cancel` 停拉新消息 → 等在途任务完成（上限 `server.shutdown_timeout`）→ 未完成者 nack requeue=true 让别的节点接走 → 关连接。原约束 #10 语义平移（「SQLite 损坏」措辞改为「连接泄漏」）。

### 4.4 Redis（R10/R11/R13）

- **客户端**：`redis.NewFailoverClient(&redis.FailoverOptions{MasterName:"deepwiki-master", SentinelAddrs:[...], Password: env})`；哨兵地址与密码由环境变量注入。
- **限流（Lua 滑动窗口，权威脚本）**：

```lua
-- KEYS[1]=窗口键  ARGV=now_ms, window_ms, limit
redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, ARGV[1]-ARGV[2])
local n = redis.call('ZCARD', KEYS[1])
if n < tonumber(ARGV[3]) then
  redis.call('ZADD', KEYS[1], ARGV[1], ARGV[1]..'-'..math.random(1,1e9))
  redis.call('PEXPIRE', KEYS[1], ARGV[2])
  return {1, tonumber(ARGV[3])-n-1}
end
return {0, 0}
```

键：`rl:ip:<ip>`（window 60s，limit=per_ip.rps×60，burst 通过 limit+burst 合并为 window limit，文档写清换算：`limit = rps*60 + burst`）、`rl:key:<key_hash>:ingest`（3600s/20）、`rl:key:<key_hash>:ask`（60s/30）、`rl:key:<key_hash>:wiki`（3600s/10）。响应头从 Lua 返回值与 TTL 计算，契约不变。
**降级**：Redis 不可用 → 进程内 x/time/rate 兜底 + WARN 日志 + health degraded（可用性优先，文档明示这是有意取舍）。
- **分布式锁**：`SET lock:refresh:<repo_id> <token> NX PX 300000`；解锁用 Lua 校验 token 后 DEL；持锁方 pipeline 正常短于 5 分钟，不引入 watchdog（超时自动释放 + CAS 兜底）。
- **事件总线**：worker 发布事件 = `XADD events:task:<task_id> * seq <n> type <t> data <json>` + `XTRIM MAXLEN ~ 1000` + `PUBLISH events:fanout <task_id>`；API 节点 `SUBSCRIBE events:fanout` → 命中本节点有连接的 task → `XRANGE` 取增量推送给 SSE/WS 客户端；SSE `Last-Event-ID` / WS `resume_from` → `XRANGE events:task:<id> <last> +` 回放。事件 payload 字段冻结（§2.5）。
- **API Key 缓存**：`auth:key:<sha256(key)>` → `{key_id,is_admin,revoked}` JSON，TTL 60s；吊销时主动 DEL。

### 4.5 etcd（R12）

- **键空间**：

```text
/deepwiki/config/<dotted.key>     # 运行时覆写值（JSON），如 /deepwiki/config/retriever.top_k
/deepwiki/config_version          # 单调递增整数（与 v1 config_version 语义一致）
/deepwiki/audit/<version>         # 每次 PUT 的审计记录 {changed_by, change, result, reject_reason, at}
```

- **加载顺序**：viper 读 yaml+env（引导）→ etcd 客户端连接 → 全量读 `/deepwiki/config/` 前缀覆盖 → `Watch(prefix)` 增量热更新 → 重建「生效配置」快照（atomic.Value）→ 通知订阅者（限流参数、chunk 参数、retriever 参数、LLM/embedding 运行时可选项）。

- **etcd 不可用**：读走本地快照缓存（可用）；PUT /config 返回 `50304 config_store_unavailable`；health degraded。
- **密钥仍只走环境变量**，禁止写入 etcd（反 AI 错误 #2 扩展措辞）。

## 10. 答辩话术更新（00 §1.4 / §13 同步）

1. 「状态唯一来源 Postgres，RabbitMQ 只传瘦消息，worker 崩溃后 Reconciler 从 DB 重建队列视图——消息系统挂了一分钟，任务一个都不丢。」
2. 「pgvector HNSW 把 10 万 chunk 的检索从暴力 O(n) 降到 ANN O(log n)，ef_search 是召回率与延迟的公开旋钮。」
3. 「OpenSearch 每仓一索引物理隔离，删仓 = 删索引，多仓库互不干扰；BM25 是工业界 20 年验证的默认排序。」
4. 「Redis Lua 滑动窗口限流在 API 多副本间全局一致；Lua 保证原子，哨兵保证高可用，Redis 挂了还有进程内兜底——可用性是有意取舍。」
5. 「etcd watch 让配置变更毫秒级推到所有节点，Txn 保证全量校验后原子生效，revision 天然审计。」
